 # 우리동네24

  ## 프로젝트 개요

  우리동네24는 지역 주민들이 일상생활에서 마주치는 다양한 불편사항들을 신고하고, 행정기관이 이를 효율적으로 관리·대응할 수 있도록
  돕는 지역 기반 신고 플랫폼입니다. 
  
  단순한 신고 시스템을 넘어, 위험 지역 정보를 활용한 안전 경로 추천 기능을 제공하여 주민들의
  실질적인 안전까지 고려한 종합 커뮤니티 안전 플랫폼입니다.

  프로젝트의 핵심 가치는 "**신고에서 끝나지 않고, 신고 데이터를 활용하여 주민의 안전을 선제적으로 보호한다**"는 점입니다. 
  
  신고된 위험 지역 정보를 기반으로 실시간 안전 경로를 추천함으로써, 데이터가 단순 기록이 아닌 실생활에 직접적으로 기여하는 선순환 구조를
  만들어냅니다.

  ## 주요 기여 및 역할

  ### 1. 전체 백엔드 아키텍처 설계 및 구현

  FastAPI 기반의 RESTful API 서버를 설계하고 구현했습니다. 
  
  주요 도메인은 다음과 같습니다:

  - 사용자 관리(User): 지역 기반 회원가입, JWT 인증, 권한 관리(User/Admin)
    
  - 신고 관리(Report): 14가지 카테고리의 다양한 불편사항 신고, 이미지 업로드(S3), 상태 관리(PENDING → CHECKED → PROCESSING →
  COMPLETED)

  - 공지사항(Notification): 행정기관의 공지 등록 및 관리
    
  - 안전 경로 추천(Routes): Tmap API와 공간 연산을 활용한 위험 회피 경로 제공

  각 도메인은 라우터(Router) - 서비스(Service) - 모델(Models) 계층으로 분리하였습니다.

  ### 2. 지역 기반 신고 시스템

  14가지 세분화된 카테고리(가로정비, 공원녹지, 교통-불법주차, 교통-장애인주차구역위반, 도로, 소방안전, 청소·쓰레기, 치산·재해, 환경,
   보건, 주택, 범죄 등)로 신고를 분류하여 행정기관이 효율적으로 대응할 수 있도록 했습니다.

  신고는 좌표(위도, 경도) 정보를 포함하며, 이는 지도 기반 조회와 안전 경로 추천 기능의 핵심 데이터가 됩니다. 
  
  신고 상태는 4단계(PENDING → CHECKED → PROCESSING → COMPLETED)로 관리되며, 관리자 권한을 가진 행정기관 담당자가 각 신고에 대해 답변하고 상태를
  전환할 수 있습니다.

  ### 3. 안전 경로 추천 시스템 (핵심 기능)
  
  신고된 위험 지역 정보를 실시간으로 활용하여, 사용자가 목적지까지 이동할 때 위험 지역을 우회하는 안전한 경로를 자동으로 계산합니다.

  #### 3.1 문제 정의 및 접근 방식

  일반적인 경로 찾기는 최단거리나 최단시간을 목표로 하지만, **위험 지역을 피하면서도 합리적인 우회 경로를 제공**해야
  합니다. 
  
  이를 위해 다음과 같은 접근 방식을 설계했습니다:

  ##### 1. 공간 데이터 활용: 단순 좌표 비교가 아닌, Shapely 라이브러리를 활용한 기하학적 연산으로 정확한 공간 관계를 계산
  ##### 2. 집합 연산 기반 안전 지역 도출: 전체 경로 영역에서 위험 지역을 차집합 연산으로 제거하여 안전 지역 추출
  ##### 3. 실제 도로망 기반 경로: 단순 직선이 아닌, Tmap API를 활용하여 실제 보행 가능한 도로를 따라 경로 생성

  #### 3.2 상세 구현 과정

  ##### Step 1: 기본 경로 조회 

  출발지와 목적지를 Tmap API에 전달하여 기본 보행자 경로를 조회합니다. 
  
  이때 WGS84 좌표계를 사용하며, 한국 영역의 유효한 좌표(위도: 33-43, 경도: 124-132)를 검증합니다.
  *프론트엔드에서 카카오맵 API를 이용하고 있어, 백엔드에서도 일관된 좌표계를 맞추기 위해 WGS84 좌표계를 사용했습니다.

  Tmap API는 경로를 반환하며, 각 feature는 LineString(경로 선분) 또는 Point(주요 지점) 타입의 경로 정보를 포함합니다
  

  ##### Step 2: 경로를 LineString으로 변환 및 버퍼 영역 생성 
  
  경로는 1차원 선(LineString)이지만, 위험 지역은 2차원 영역입니다. 따라서 경로 주변에 버퍼 영역을
  생성하여 "**경로 근처의 위험 지역**"을 감지할 수 있도록 합니다.

  버퍼 거리는 미터 단위로 입력받지만, WGS84 좌표계는 도 단위이므로 변환이 필요합니다

  **위도 1도 ≈ 111km라는 근사값 활용**
  이렇게 생성된 route_polygon은 경로를 중심으로 반경 100m(기본값) 내의 모든 영역을 포함하는 Polygon 객체가 됩니다.

  ##### Step 3: 데이터베이스에서 위험 지역 조회

 이미 해결된 문제는 더 이상 위험 지역이 아니므로, COMPLATED 상태의 신고 지역을 제외한 유효한 위험 지역만 고려합니다.

  ##### Step 4: 차집합 연산으로 안전 지역 계산

  - 전체 경로 영역을 집합 A라고 하면
  - 각 위험 지역을 집합 $B₁, B₂, ..., Bₙ$이라 할 때
  - 안전 지역 = $A - B₁ - B₂ - ... - Bₙ$

  이 차집합 연산의 결과는 다음 중 하나입니다.
  1. 하나의 연속된 안전 지역 → 중심점 1개 반환
  2. 여러 개로 분리된 안전 지역 → 각 영역의 중심점 반환
  3. 안전 지역이 없음 → 빈 리스트 반환

  ##### 왜 중심점(Centroid)을 사용하는가?
  각 안전 지역의 중심점은 해당 영역에서 위험 지역으로부터 가장 균형잡힌 위치입니다. 
  
  이 점을 경유지로 설정하면 위험 지역을 최대한 회피하면서도 자연스러운 경로를 만들 수 있습니다.

  #### Step 5: 경유지를 거치는 실제 경로 재계산 
  
  앞서 계산한 waypoints는 "어디를 거쳐가야 하는지"에 대한 좌표일 뿐, 실제 도로를 따라 이동하는 경로가 아닙니다.
  
  따라서 각 구간마다 Tmap API를 다시 호출하여 실제 보행 가능한 경로를 조회합니다.

  예시:
  - 경유지가 2개 발견된 경우: [출발지, 경유지1, 경유지2, 목적지]
  - 총 3번의 Tmap API 호출 발생:
    a. 출발지 → 경유지1
    b. 경유지1 → 경유지2
    c. 경유지2 → 목적지
  - 각 구간의 좌표를 모두 연결하여 하나의 연속된 경로 생성

  이렇게 하면 단순 직선이 아닌, 실제 도로망을 따라 위험 지역을 우회하는 자연스러운 경로가 만들어집니다.
  

  ## 사용 기술 스택
  ### Backend Framework
  - FastAPI: 비동기 처리, 자동 API 문서화, Pydantic 기반 데이터 검증
  - SQLAlchemy: ORM을 통한 데이터베이스 추상화, 관계형 데이터 모델링
  - PyMySQL: MySQL 데이터베이스 연결

  ### 공간 정보 처리

  - Shapely: LineString, Polygon, Point 등 기하학적 객체 생성 및 공간 연산
  - Tmap API: 실제 보행자 경로 데이터 제공
